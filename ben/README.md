# Ben Code

A personal fork of [T3 Code](https://github.com/pingdotgg/t3code) (MIT). Branch `ben-code`, remote `upstream`
(push disabled). All Ben Code code lives in `apps/web/src/components/ben/`, `apps/web/src/routes/_chat.board.tsx`
and `ben/`, plus a three-line switch in `AppSidebarLayout.tsx`, so rebasing on upstream rarely conflicts.

## Run it

    ben/run.sh            # on a snapshot copy of ~/.t3 (~/.t3-ben); prints the pairing URL
    ben/run.sh --reseed   # re-snapshot your current T3 data

The copy never writes to the nightly app's data. `BEN_CODE_HOME=~/.t3 ben/run.sh` runs on your real data;
quit the nightly app first. The schema level is the same as the nightly build today (migration 80).

## What it adds

- **Board** (`/board`): Needs you, Working, Idle, Finished, Pushed. Columns come from live thread state, so cards
  move by themselves. Drag a card to Finished to settle it, or to Idle to reopen it. Filter by project.
  The sidebar's Board button swaps to "Back to threads".
- **Project accordion sidebar**: the open project shows its Planner, Merge manager and threads grouped by state.
  Other projects are single rows at the bottom, with an amber count when something needs you.
  `localStorage.setItem("ben:sidebar", "false")` brings the upstream sidebar back.
- **Planner** (read-only): runs on provider instance `claudeAgent_planner`, whose Claude home
  (`~/.claude-planner`, built by `ben/sync_planner_home.py`) denies Edit, Write and destructive shell commands.
  It plans, then starts threads with `t3_thread_launch`. First click creates it; it is remembered per project.
- **Merge manager**: long-lived, ships finished work one change at a time, watches CI, fixes failures.
- **Dream** (`ben/dream_notes.py`, launchd job `com.ben.dream-notes`, 03:30 daily): distills recent sessions into
  `~/.agents/planner-notes/` (index, lessons, frustrations, open work, decisions) with a backup before each run.
- **Usage** (`proxy-usage` or `ben/proxy_usage.py`): per-account weekly usage and reset time from the proxy.

## Updating

`ben/sync_upstream.sh` fetches upstream, rebases `ben-code`, reinstalls, typechecks and runs the board tests.
On a conflict it aborts and leaves the branch as it was. Nothing pushes.

## Known gaps

- It runs from source, not as a packaged app. A packaged build needs Rust (`cargo` is not installed) and would
  need its auto-updater pointed away from the official feed, or it would replace itself with upstream.
- The Planner title is regenerated by T3 after its first turn; the sidebar finds it by remembered id.
- Dream notes come from a cheap model. Read `~/.agents/planner-notes/` before trusting it; one early note
  misread a dev-server event as a frustration.
- Board drag only settles and reopens. Moving cards into Working or Pushed is the agent's job.
